# PubShip 0.24.2

Clearer tool definitions for assistants, accurate approval hints and stronger checks that packaged installs expose the same contracts as source.

## Changed

- Describe every input parameter across default local, opt-in local and operator self-host tools, including formats, pagination, prerequisites and result semantics. (#8)
- Correct preparation and self-host download hints to reflect temporary state changes. Clients may adjust approval prompts; execution permissions and confirmation gates are unchanged. (#8)
- Apply the final PubShip artwork to repository assets and operator self-host pages. (#3, #5)

## Fixed

- Reject incomplete, stale or substituted offline TDQS reports and preserve literal data fields in contract checks. Distribution comparisons now distinguish JSON values such as true and 1. (#10)
- Keep synthetic edit expiry stable across clock boundaries while preserving production rejection of genuinely changed edits. (#9, #12)

## Validation

All three actual MCP tool profiles are checked: 13 default local tools, 41 local opt-in tools and 46 operator self-host tools. Release acceptance includes the complete synthetic suite, browser and container checks, source/wheel/sdist definition parity, lint, generators, package inspection and secret scanning. CI requires 100% statement and branch coverage across the five TDQS-owned modules. This is not whole-application coverage or a new model-scored TDQS grade. No real Google API calls are part of release validation.

Local setup, credentials, supported operations and the operator-only self-host boundary remain unchanged. Upgrade with `uvx --refresh pubship@0.24.2 --check` after PyPI publication. Publishing workflows verify the release commit and checksums before publishing the exact attached artifacts.
